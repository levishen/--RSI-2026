## 这个实验在做什么

配合讲授《递归之桥》的后 1 小时使用。你会亲手跑一个最小的递归自我改进循环：

```text
U = R ∘ (F ∘ P)
P 提议：优化器读反馈，改写阅卷 Agent 的"技能文档"
F 打分：给每份作业的阅卷结论打分
R 采纳：决定这次改动留不留
```

场景就是讲授开头那门课：作业交给阅卷 Agent 批改。老师的评分细则（`policy.py`，虚构）写成了代码，能对每份作业算出唯一正确的结论：满分、扣分、零分、转人工。**Agent 看不到这份代码**，它的初始技能文档只有一句含糊的话。循环要靠反馈，把细则"学"出来。

> 所有"彩排结果"都是讲师 2026-10-28 用 `claude-sonnet-4-6` 真跑的，原始文件在 `rehearsal_outputs/`。模型有随机性，**你的数字会不同**。读结果时，先问一句：样本够不够？这正是追问 5 要讲的。

## 1 · 认识系统（5′）

1. `data/train.json`：任意看几份作业。字段有：
   - 通用：id、kind（编程题 / 计算题 / 实验报告 / 论述题）、attachment（缺失时为 null）、similarity_pct（查重相似度，百分数）、late_hours（迟交小时数）、leave（有没有请假条）。
   - 编程题：tests_passed、tests_total；计算题：answer_correct、has_steps；实验报告：words；论述题：words、refs（引用数）。
   - `label` 是细则答案，Agent 看不到。
2. `loop.py` 里的 `SKILL0`：Agent 的初始技能文档，只有一句话。
3. `policy.py` 开头的评分细则。注意三个陷阱：
   - 查重 ≥ 50% 是**转人工**，不是零分；
   - 计算题答案错、但有过程，给**扣分**，不给零分；
   - **有请假条的迟交不扣分**；没请假条时，迟交超过 72 小时才判零分，72 小时以内只把满分降为扣分。

数据分两份：**训练集** 36 份，循环用它打分、做决定；**锚集** 40 份，**从不参与任何决定**，只用细则答案对账。起点准确率：训练集 42%，锚集 60%。

## 2 · 实验一：四种 F × R（20′）

四人一组，每人跑一种（每次约 6–8 分钟、约 460 次调用）：

| 成员 | 命令 | F（打分） | R（采纳准则） | 对应追问 |
|---|---|---|---|---|
| A | `python3 loop.py --signal v2 --accept fails` | V2：和细则答案比对 | 只看本轮那 8 份失败作业有没有变好 | 2、3 |
| B | `python3 loop.py --signal v2 --accept ineq` | V2 | 采纳不等式：失败作业收益 − 其他作业损失 > 1 份 | 3 |
| C | `python3 loop.py --signal v2 --accept sign` | V2 | 精确单侧符号检验：p < 0.05 才采纳 | 3、5 |
| D | `python3 loop.py --signal v6 --accept ineq` | V6：Agent 自报的把握 | 采纳不等式 | 1 |

**D 跑完后，马上接着跑实验二的命令**（d = 1 循环约 13 分钟），其他人先讨论。

输出每轮一行：

| 列 | 含义 |
|---|---|
| 轮 | 第几轮（0 是起点） |
| F 信号 | **循环自己看到的分数**（0–1） |
| 训练集真实、锚集真实 | 用细则答案对账的**真实**准确率，循环看不到 |
| 改坏 | 本轮采纳后，原来判对、现在判错的训练作业份数 |
| 决定 | 采纳还是拒绝；行尾是依据（fails：失败作业得分变化；ineq：收益和损失；sign：变好、变差份数和 p） |
| 文档字数 | 技能文档有多长 |

**彩排结果**（起点：训练 42%，锚集 60%；起点会因随机性浮动几个百分点）：

```text
A  v2 + fails  最后一轮：F 1.00  训练 100%  锚集 88%（另一次：0.97 / 97% / 88%）
B  v2 + ineq   最后一轮：F 0.97  训练 97%   锚集 85%（另一次：0.89 / 89% / 92%）
C  v2 + sign   最后一轮：F 1.00  训练 100%  锚集 90%（另一次：0.81 / 81% / 78%）
D  v6 + ineq   自报把握 0.83 → 0.92，训练真实 42% → 47%，锚集 60% → 52%
```

注意 D 只是讲师那一次的结果：独立复现那次，自报把握同样涨到 0.92，锚集却是 60% → 65%。**单次运行说明不了自评好不好**，要看收尾时全班合起来的 ρ 区间。

**组内讨论**：

1. D：循环看到的分数在涨，在没见过的作业上却判得更差。用追问 1 解释。
2. A：训练集刷到了 100%，锚集为什么只有 88%？（追问 2）
3. A、B：把每次"采纳"那一行的修好 b、改坏 c 代入 z = (b − c)/√(b + c)，有几次超过 1.64？（追问 3）
4. C 采纳得最少。它是太保守，还是每次都站得住？

## 3 · 实验二：递归度 d = 1（10′）

```bash
python3 loop.py --signal v5 --accept ineq --d 1
python3 audit.py runs/<刚才那次运行的文件名>.json
```

这次优化器除了改技能文档，**还能改裁判（V5）的评审标准**。`audit.py` 用细则答案给每一轮的候选对账，不管它被采纳还是被拒绝。它会重新调用模型给候选判一遍（约 450 次、5 分钟），所以数字和循环当时的记录相差几个百分点是正常的；来不及就直接看 `rehearsal_outputs/d1_audit.txt`。

**彩排结果**：5 轮全部被拒；其中 4 轮优化器改写了评审标准。对账发现，**第 1 轮的候选其实是好改动**：锚集准确率从 60% 提到 72%。它被拒，是因为评审标准同时被改写了，新标准下得分更低。其余几轮的候选有好有坏。

讨论：

1. 评审标准每轮都在变，"新版比旧版分高"还有意义吗？
2. 这次是好改动被错杀。如果优化器把标准改**松**，会发生什么？讲授里"三条分离"的哪一条能防住它？

## 4 · 做展示页（10′）

三步，生成一页可以直接投屏的小组展示：

1. **汇总**：组长电脑上新建文件夹 `group/`，每位组员把自己 `runs/` 里的 json 发给组长放进去（微信、U 盘都行）。
2. **写三句话**：把 `结论模板.md` 复制成 `group/结论.md`，每段写一两句：
   - 我们看到了什么
   - 用哪个追问解释（分数可信吗？用分数挑会被骗吗？这次改动真的变好了吗？留下的改动有多少真好？样本够吗？）
   - 一个意外，或我们不同意的地方
3. **生成**：

```bash
python3 showcase.py --group "第 3 组" --dir group
```

得到 `展示_第3组.html`，用浏览器打开、全屏。页面上有：每次运行一张曲线图（循环看到的分数、训练集真实、锚集真实，虚线是被采纳的轮次，并自动标注"真实进步 / 循环自以为进步了 / 变化在噪声内"）、你们的三句结论、关键数字表、锚集最高那次 AI 写出的细则节选。

接口出问题的组，用 `rehearsal_outputs/` 里的 json 照样能生成展示页。

## 5 · 小组展示（每组 2 分钟）

讲清三件事：

1. **我们看到了什么**：指着图讲，哪条线在涨、哪条没涨；哪次是真实进步，哪次是"循环自以为进步了"？
2. **用哪个追问解释**：选一个，说清楚为什么。
3. **一个意外**：和讲师彩排不一样的地方，或者不同意讲授内容的地方。不一样才最有价值。

其他组每组最多问一个问题，例如："这个结论是一次运行得出来的，还是几次？""锚集上的进步，超过随机跳动了吗？""AI 写的细则里，有哪条是错的？"

## 讲师收尾：全班数据对账

讲师把各组的 json 放进同一个文件夹，运行：

```bash
python3 principles.py <全班汇总文件夹>
```

它会按五个追问各输出一段，样本小的地方都带 n 和区间。讲师彩排（9 次运行、45 个候选）的结果：

```text
追问1  ρ：v2 +0.63 [+0.35, +0.81] n=30；v5 −0.60 [−0.89, +0.06] n=10；v6 −0.05 [−0.89, +0.87] n=5
追问2  被采纳改动的"训练涨幅 − 锚集涨幅"：fails +6.5% ± 2.5%；ineq +9.1% ± 8.1%；sign +16.6% ± 5.0%
追问3  fails 采纳 9 次：7 次 p ≥ 0.05；ineq 采纳 5 次：3 次 p ≥ 0.05；sign 采纳 3 次：0 次
追问4  （真好 = 锚集多对 ≥ 3 份）fails FPR 6/7，被采纳的里真好 3/9；ineq FPR 1/5，4/5；sign FPR 0/3，3/3
追问5  锚集 40 份：两版 12 份结论不同时，要 10 好 2 坏（净多对 20%）才显著
```

全班数据合在一起后，各组的"意外"在这里得到检验：先问样本够不够，再看全班数据支不支持。`python3 summarize.py <文件夹>` 可以看每种配置的最终结果；± 是标准误，运行次数越多越小。

## 课后挑战

- **加大验证预算**：把 `policy.py` 里训练集改成 144 份（`make(144, TRAIN_SEED, 1)`），重新生成数据，再跑 C。符号检验采纳得更多了吗？
- **改细则**：加一条规则（比如"编程题代码超过 500 行转人工"），看循环多久能学会。
- **调评估误差**：讲授第 16 页说"评估误差应随 √(b+c) 增长"，而 `--accept ineq` 用的是常数 `--eps 1`。试试 `--eps 3`，采纳次数和改坏份数怎么变？
- **去相关**：把 V5 裁判换成另一个模型（改 `judge()` 里的 model），看 ρ 会不会变高。

## 故障处理

| 现象 | 处理 |
|---|---|
| `请先在 .env 里填好 LLM_BASE_URL 和 LLM_API_KEY` | 确认 `.env` 在仓库根目录（不是 `.env.example`），且已填好 |
| `接口报错 401` | key 错了 |
| `接口报错 404` 或网络错误 | 网关地址要以 `/v1` 结尾 |
| 很慢、`429` | 全班同时跑：把 `.env` 里的 `LLM_WORKERS` 改成 2，或直接用 `rehearsal_outputs/` 的数据讨论 |
| 中文乱码（Windows） | 先执行 `chcp 65001` |

## 仓库结构

